01 / ArchMind Architecture AI Practice Workspace

ArchMindArchitecture AI Practice Workspace

Current public concentrated development period: 2026.08.06

This is not a one-off image-generation demo. It packages real design problems, structured prompting, review methods and team templates into a reusable AI practice demo that colleagues can try, explain and evaluate before scaling.

  • SU input
  • TaskSpec
  • Review
  • Toolkit
User scenario

Architecture teams need to turn personal AI prompting from SU screenshots to presentation output into a reusable team process.

Key decision

Prompting is treated as a structured design task: define input, locked elements, editable variables, blocked changes and validation rules.

Current evidence

Four real SU-to-render prompt cases, one lightweight reviewable demo prototype and a team adoption toolkit sample.

Project boundary

This is proposal and prototype material for practice adoption; it is not claimed to be a complete enterprise platform or production system.

My contribution

I organized real design pain points into SU-to-render prompt cases, structured TaskSpecs, review methods, demo videos and a toolkit sample so individual AI experiments can be reused, explained and discussed by the team.

02 / Construction early warning

BuildLoop AIConstruction loop

Current public concentrated development period: 2026.08.06

A locally auditable construction early-warning agent that connects drawings, BIM, standards, meetings, messages and site reports into reviewable, approvable and closable project items.

  • Evidence
  • Approval
  • Closeout
  • Evaluation
User scenario

A construction manager needs to compare many sources at once and catch weak signals between drawing revisions, BIM conflicts, code requirements and site deviations.

Key decision

An alert is not a conclusion. Every alert must carry source location, risk level, recommended action, approval state, execution trace and closeout evidence.

Current evidence

README records the baseline: 283 tests passed, 2 optional PostgreSQL integration tests skip without a database, and evaluation covers risk level, evidence location, recommended action and approval drafts.

Project boundary

The default analysis is local deterministic logic. External model enhancement and Feishu / Lark webhooks must be enabled explicitly and are not production claims.

My contribution

I organized multi-source parsing, evidence location, alert triage, human execution and closeout records into an auditable process, then fed the actions back into later evaluation and rule calibration data.

03 / PeopleOps workflow

PeopleOpsSmart workspace

Current public concentrated development period: 2026.06.16 - 2026.07.12

Not an HR chatbot, but an agent workspace that puts policy answers, candidate actions, human approvals and audit into one linked workflow.

  • RBAC
  • PII
  • Approval flow
  • Audit
User scenario

For HRBPs and recruiting operations, this connects policy Q&A, candidate actions, human approval and audit into one traceable flow.

Key decision

Candidate analysis only outputs source evidence. External actions begin as drafts and must be explicitly submitted and approved before execution.

Current evidence

On 2026-07-13, 47 / 47 unit tests and 25 / 25 offline cases passed, with failure cases and fixes preserved.

Project boundary

This is a local prototype and deterministic safety regression; it does not represent real user outcomes, external connector availability or live model quality.
